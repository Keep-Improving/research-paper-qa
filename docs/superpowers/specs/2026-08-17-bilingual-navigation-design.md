# 中英双语与研究者优先导航设计

## 目标

为网站增加完整的中英双语界面，并降低普通研究者首次使用时的导航复杂度。网站界面文案支持中英文切换，但论文标题、摘要、用户提问、回答等数据库内容保持原文，不做运行时自动翻译。

## 用户与范围

- 主用户：阅读论文、搜索问题和参与讨论的普通研究者。
- 覆盖范围：网站全部页面；Chrome 插件不在本次范围内。
- 默认语言：首次访问根据浏览器语言自动选择；中文浏览器使用中文，其他语言环境使用英文。
- 手动选择：用户在顶部点击“中 / EN”后立即切换，选择保存到 cookie，并在后续访问中优先使用。

## 导航设计

普通用户的一级导航为：

**搜索｜论文｜问题｜我的｜中 / EN**

- “我的”是个人工作台，包含我的收藏、我的提问、我的回复和最近浏览。
- 登录且具备作者权限时，“我的”增加作者工作台和论文认领入口。
- 管理员审核入口仍放在“更多”或管理区域，不混入普通用户的个人内容。
- 锚点不再占用一级导航，在论文详情、问题详情中作为上下文入口；需要直接浏览时放入“更多”。
- 未登录用户访问“我的”时看到登录提示和功能说明，而不是空白页面。
- 移动端折叠主导航，但语言切换在菜单顶部保持可见。

## 语言架构

### LocaleProvider

客户端语言状态由 `LocaleProvider` 管理。初始值来自服务端解析的 cookie；无 cookie 时由请求的 `Accept-Language` 推断。用户切换后更新 cookie 并刷新当前路由，保留搜索条件和当前页面。

### 翻译字典

界面文案集中放在 `messages/zh-CN.ts` 和 `messages/en-US.ts`。组件通过稳定的消息 key 读取文案，避免在 JSX 中散落条件判断。数据库内容不进入翻译字典。

### LanguageToggle

顶部显示紧凑的“中 / EN”按钮，具备当前状态和无障碍标签。切换不改变 URL 结构，不影响服务器端数据查询。

## “我的”页面

新增或重构 `/me` 页面，使用现有数据访问逻辑聚合个人数据：

- 收藏：复用 collections 查询。
- 我的提问和回复：复用 discussions 查询，并显示状态与最近更新时间。
- 作者功能：仅在当前用户具备对应身份或权限时显示工作台、论文认领和待处理作者回应。
- 后续通知、草稿、关注论文等个人功能可继续扩展到此页面。

## 轻量引导

不引入多步骤 Tour。仅保留两个可关闭提示：

1. 首页搜索框下方提示“输入论文标题、DOI 或问题关键词开始”。
2. 用户首次打开论文详情时提示可在段落、图表或公式旁发起讨论。

关闭状态保存在浏览器本地，不写入数据库。

## 验收标准

- 首次访问语言符合浏览器语言；手动选择后刷新和重新打开仍保留选择。
- 所有网站页面的界面文案均能切换中英文，数据库中的用户内容保持原文。
- 普通用户一级导航只显示搜索、论文、问题、我的和语言切换。
- 普通用户看不到作者工作台和管理审核入口；有权限用户可以从“我的”进入作者功能。
- “我的”页面能展示收藏、提问和回复，未登录状态有明确登录引导。
- 锚点仍可从论文/问题上下文进入，直接浏览入口收纳在更多区域。
- 现有登录、论文浏览、问题创建、回复、收藏和作者权限流程无回归。

## 实施顺序

1. 建立消息字典、服务端 locale 推断和客户端 Provider。
2. 添加语言切换按钮并迁移全局 Shell、认证和核心浏览页面文案。
3. 重构主导航和按角色显示的“更多”入口。
4. 新增/重构“我的”页面，接入现有查询逻辑。
5. 添加两个轻量引导提示。
6. 运行类型检查、单元测试、构建和浏览器交互验证。
