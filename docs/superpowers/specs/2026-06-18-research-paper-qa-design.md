# 科研文献问答库 PRD / 设计规格

日期：2026-06-18

## 1. 产品定位

科研文献问答库是一个按文献聚合的人类问答与评论系统。它通过浏览器插件把讨论带到读者正在阅读论文的现场，同时通过独立网站沉淀文献、问题、评论、引用锚点、收藏和作者回应。

第一版采用“浏览器插件 + 独立网站”的双完整客户端模式。插件不是网站的简化跳板，而是可在单篇文献内完成主要讨论操作的完整客户端；网站负责跨文献检索、收藏管理、作者认证、个人主页和内容治理。

## 2. 第一版范围

### 2.1 核心闭环

1. 用户在论文网页、DOI 页面、arXiv、PubMed、出版社页面或可识别 PDF 页面打开浏览器插件。
2. 插件识别当前文献的 DOI、arXiv ID、PMID、标题或 URL，匹配或创建文献记录。
3. 插件侧边栏显示该文献的完整讨论内容，支持筛选、排序、提问、回答、评论、投票、收藏和举报。
4. 用户可以选中原文、拖拽图片或截图到插件提问入口，创建带引用锚点的新问题。
5. 网站文献详情页展示与插件一致的讨论数据，并提供更完整的检索、收藏、作者认证和治理能力。
6. 只有该文献的第一作者用户和通讯作者用户可以发布带“作者回应”标签的内容。
7. AI 第一版只做辅助和治理建议，不作为论文内容的权威回答来源。

### 2.2 第一版暂不做

- Zotero、Obsidian、Notion 等插件不进入第一版实现，但后端接口预留扩展空间。
- 不做 AI 基于全文直接回答论文问题。
- 不做复杂声誉体系，先保留基础投票、举报、作者标识和收藏。
- 不把争议状态作为系统裁判结论，只作为“存在争议”的提示和排序信号。

## 3. 产品模块

### 3.1 文献识别与收录

插件和网站都可以通过 DOI、arXiv ID、PMID、URL、标题等信息匹配文献。稳定标识的优先级高于标题和 URL。没有稳定标识时，系统创建待合并文献记录，后续由系统规则或管理员合并。

### 3.2 讨论系统

讨论对象包括：

- 问题
- 回答
- 评论
- 作者回应
- 勘误或补充说明
- 复现实验记录

每条讨论内容可以绑定整篇文献，也可以绑定一个引用锚点。问题状态包括未回答、已回答、已解决、作者已回应、存在争议、已隐藏。

“存在争议”是系统计算状态加人工可覆盖标记。判断信号包括赞同与反对同时较高、多轮反驳、事实错误举报、作者回应后仍有高质量反驳、管理员或领域版主手动标记。第一版只显示争议提示，不裁定谁正确。

### 3.3 引用锚点系统

锚点来源包括：

- 文本选区
- 图片或图表拖拽
- 截图
- 手动页码、章节、图号、表号、公式号、参考文献号

插件优先承担锚点创建，网站负责展示、管理、筛选和检索。浏览器插件对不同出版社网页、PDF 查看器、跨域图片和 canvas 的支持不一致，因此第一版必须保证文本选区创建问题优先稳定；图片拖拽和截图作为增强能力，并提供手动回退。

### 3.4 插件侧边栏

插件侧边栏是单篇文献内的完整讨论客户端，提供：

- 文献识别和手动补全
- 完整讨论列表
- 筛选和排序
- 提问、回答、评论
- 投票、收藏、举报
- 作者回应查看
- 引用当前选区提问
- 拖拽图片或截图提问
- 相似问题提示

### 3.5 独立网站

网站提供：

- 文献搜索
- 文献详情页
- 问题详情页
- 锚点详情页
- 收藏库
- 个人主页
- 通知中心
- 作者认证
- 作者工作台
- 内容治理后台

### 3.6 作者认证与作者回应

用户身份分为全站身份和文献身份。

全站身份包括普通用户、认证科研人员、管理员等。文献身份包括第一作者、通讯作者、共同作者、非作者。

只有某篇文献的第一作者用户和通讯作者用户可以对该文献发布带“作者回应”标签的内容。共同作者可以认证为本文作者，但默认不能发布“作者回应”，除非后续支持第一作者或通讯作者授权。

第一作者和通讯作者也可以像普通用户一样对自己的文献提问、回答、评论。这些普通互动不会自动带作者回应标签。发布时需要明确选择“以作者回应发布”，且只有有权限的用户能看到该选项。

### 3.7 AI 辅助与治理

AI 第一版只做辅助：

- 重复问题提示
- 相似锚点提示
- 问题标题优化建议
- 标签建议
- 讨论摘要
- 垃圾内容和风险内容提示

AI 不自动发布回答，不自动删除内容，不替用户或管理员判断权威结论。

## 4. 核心用户流程

### 4.1 读者提问

1. 用户打开论文页面。
2. 插件识别文献，无法识别时进入手动补全。
3. 用户选中文本、拖拽图表或截图到插件提问入口。
4. 插件生成引用锚点和问题草稿。
5. 系统提示相似问题或相似锚点。
6. 用户补充问题正文并提交。
7. 问题同步出现在插件和网站文献页。

### 4.2 读者浏览讨论

1. 用户打开插件或网站文献页。
2. 用户选择视图：全部、问答、作者回应、按锚点、热门、未回答、已解决。
3. 用户选择排序：最新、最近活跃、投票、热度、争议度、锚点位置。
4. 用户阅读、收藏、投票、回复或举报。

### 4.3 作者回应

1. 作者登录网站。
2. 作者提交第一作者或通讯作者认证。
3. 审核通过后进入作者工作台。
4. 作者按热度、未回答、被提及锚点筛选待回应问题。
5. 作者选择“以作者回应发布”并提交。
6. 作者回应在插件和网站中高亮，并可被单独筛选。

### 4.4 内容治理

1. 用户举报内容。
2. AI 给出风险类型建议。
3. 管理员查看举报队列。
4. 管理员处理隐藏、恢复、合并重复问题、标记争议、合并重复文献或封禁账号。

## 5. 数据模型

### 5.1 User

记录账号、显示名、机构、ORCID、邮箱、角色、信誉基础数据、通知偏好。

### 5.2 Paper

记录标题、作者列表、DOI、arXiv ID、PMID、期刊或会议、年份、URL、摘要、出版商、PDF URL、合并状态。

### 5.3 PaperAuthorClaim

记录用户对某篇文献的作者身份认证：用户 ID、文献 ID、声明角色、证据类型、审核状态。声明角色包括 first_author、corresponding_author、co_author。只有 first_author 和 corresponding_author 可获得作者回应权限。

### 5.4 Anchor

记录文献 ID、锚点类型、引用文本、上下文文本、页码、章节、图号、表号、公式号、参考文献号、来源 URL、DOM 路径、PDF 页码、图片或截图文件、OCR/caption、embedding、规范化标签。

### 5.5 DiscussionItem

统一记录问题、回答、评论、作者回应、勘误或补充说明、复现实验记录。字段包括文献 ID、锚点 ID、父级 ID、作者用户 ID、内容类型、正文、状态、是否作者回应、是否置顶、是否隐藏、创建时间、更新时间。

### 5.6 Vote / Reaction

记录赞同、反对、感谢、有帮助、需要澄清等反馈。第一版至少支持赞同、反对、有帮助。

### 5.7 Collection

记录用户收藏的文献、问题、锚点或讨论串，支持标签和备注。

### 5.8 ModerationReport

记录举报、AI 风险提示、管理员处理状态和处理结果。

### 5.9 Notification

记录被回复、作者回应、收藏文献有新问题、关注锚点有更新、认证审核结果等通知。

## 6. 相似锚点和相似问题检索

锚点不能只存字符串，必须结构化保存并支持三层检索：

1. 精确和结构化匹配：同一文献、同一图号、页码、章节、公式号或参考文献号。
2. 文本相似：引用文本、上下文、用户问题标题和正文做全文检索。
3. 语义相似：对引用文本、OCR/caption、问题内容生成 embedding，查找语义相近的问题和锚点。

用户创建带锚点问题时，系统先检索相似锚点和相似问题。如果已有相关讨论，插件和网站都应提示用户先查看或关联已有讨论。

## 7. 权限规则

- 未登录用户：可浏览公开文献讨论和筛选排序，不能发帖、投票、收藏、举报。
- 登录普通用户：可提问、回答、评论、投票、收藏、举报、创建锚点。
- 认证科研人员：拥有认证标识，但没有自动作者回应权限。
- 本文共同作者：可显示“本文共同作者”身份，但不能默认发布作者回应。
- 本文第一作者或通讯作者：可选择发布作者回应，也可发布普通问题、回答、评论。
- 管理员或版主：可隐藏内容、处理举报、合并重复问题、合并重复文献、调整锚点标签、撤销误标状态。
- AI：只产生建议和风险提示，不直接删除、发布或替用户定性争议。

## 8. 筛选和排序

### 8.1 筛选维度

- 内容类型：问题、回答、评论、作者回应、勘误或补充、复现实验记录。
- 状态：未回答、已回答、已解决、作者已回应、存在争议、已隐藏。
- 锚点：整篇文献、章节、页码、图、表、公式、参考文献、文本选区、图片或截图。
- 参与者：作者回应、本文作者参与、我参与的、我收藏的。
- 质量和治理：高赞、高反对、被举报、需要澄清、疑似重复。
- 时间：最新创建、最近活跃、指定时间段。

### 8.2 排序规则

- 最新：按创建时间倒序。
- 最近活跃：按最近回答、评论、作者回应、状态变化排序。
- 投票：按赞同数、反对数和有帮助反馈综合排序。
- 热度：浏览、收藏、回复、投票、最近活跃、作者参与综合。
- 争议度：反对票、反驳回复、事实错误举报、作者回应后继续争论等综合。
- 锚点位置：按章节、页码、图表、公式编号或用户手动排序。
- 未解决优先：未回答、无作者回应、高热度问题靠前。

## 9. 系统架构

### 9.1 前端网站

独立 Web App，负责文献检索、文献详情页、完整讨论、收藏、个人中心、作者认证、治理后台。

### 9.2 浏览器插件

Manifest V3 插件，包含 content script、background service worker、side panel/sidebar UI。

content script 负责识别页面文献、读取选区、捕获拖拽或截图锚点。sidebar UI 负责完整讨论交互。

### 9.3 后端 API

统一服务插件和网站，提供认证、文献匹配、讨论、锚点、投票、收藏、举报、通知、作者认证。

### 9.4 数据和存储

关系数据库保存核心业务数据。全文检索用于标题、正文、引用文本。向量检索用于相似锚点和相似问题。文件存储保存截图、图表引用图片、OCR 结果等。

### 9.5 AI 辅助服务

AI 可以作为异步任务或后端模块，用于相似问题提示、摘要、标签建议、风险提示。

## 10. 插件技术边界

- 文献识别优先级：DOI meta tag、citation meta tag、arXiv ID、PMID、URL pattern、页面标题。
- 文本锚点：优先支持普通网页选区和可访问 PDF 文本层，保存选中文本、前后文、URL、页面标题、可选 DOM selector。
- 图片和图表锚点：优先支持拖拽网页图片和用户截图。跨域图片、canvas、部分 PDF 查看器可能无法直接读取原图，需要回退到截图或手动锚点。
- 拖拽提问入口：侧边栏提供固定 drop zone。用户选中文本、拖入图片或点击“引用当前选区提问”后生成问题草稿。
- 离线或失败回退：文献识别失败时允许用户手动输入 DOI 或标题；锚点捕获失败时允许手动填写页码、图号、章节。
- 插件和网站功能一致性：插件提供单篇文献内完整讨论能力；网站提供跨文献管理和治理能力。

## 11. 网站页面结构

- 首页/搜索页：搜索文献、问题、作者回应、锚点。
- 文献详情页：文献元数据、收藏、讨论筛选排序、锚点视图、作者回应、热门和未回答问题。
- 问题详情页：问题、引用锚点、回答、评论、作者回应、相似问题。
- 锚点详情页：引用文本或图片、定位信息、相关问题和讨论。
- 收藏库：用户收藏的文献、问题、锚点、讨论串。
- 个人主页：用户提问、回答、收藏、认证状态、通知设置。
- 作者认证页：选择文献、声明第一作者、通讯作者或共同作者，提交 ORCID、邮箱或人工审核证据。
- 作者工作台：自己有回应权限的文献、待回应高热问题、未回答问题、被提及锚点。
- 治理后台：举报队列、疑似重复、争议讨论、文献合并、锚点标签调整。

## 12. UI 风格方向

Reading this as: 科研学术协作产品，面向读者、论文作者和管理员，适合克制、清晰、高信息密度的学术工具风格。

UI 应避免营销感、装饰性强的视觉和过度动效。整体方向：

- 信息密度中高，优先可扫描、可检索、可比较。
- 视觉风格克制，接近科研数据库、文献管理器和专业协作工具。
- 用清晰层级区分文献元数据、问题、回答、作者回应、引用锚点和治理状态。
- 颜色以中性背景和少量语义色为主，不使用大面积紫蓝渐变、玻璃拟态或花哨插画。
- 卡片只用于独立讨论项、弹窗或确实需要框定的工具，不在页面里层层套卡片。
- 插件侧边栏需要紧凑，重点是筛选、排序、引用锚点、讨论正文和操作按钮。
- 网站适合长时间阅读和管理，表格、列表、分栏和筛选面板应稳定、可键盘操作、移动端可折叠。
- 所有主要流程必须有加载、空状态、错误状态和失败回退。

推荐 UI 基调：学术数据库 + GitHub issue discussion + Zotero 风格的工作台，而不是社交媒体信息流或营销页。

## 13. 验收标准

- 在至少 arXiv、PubMed、DOI landing page 和一个出版社页面中，插件能识别文献或进入手动补全流程。
- 插件侧边栏能显示完整讨论列表，并完成筛选、排序、提问、回答、评论、投票、收藏、举报。
- 用户能通过选中文本创建带引用锚点的问题。
- 用户能通过拖拽图片或截图创建带图片锚点的问题；失败时能回退到手动锚点。
- 网站能搜索文献和讨论，打开文献详情页后看到与插件一致的数据。
- 认证第一作者或通讯作者能发布“作者回应”；共同作者和普通用户不能发布该标签内容。
- 作者用户也能以普通身份提问、回答、评论，不自动带作者回应标签。
- 新问题提交前能提示相似问题或相似锚点。
- AI 只生成建议，不自动删除内容、不自动发布回答、不自动替用户判断权威答案。
- 管理员能处理举报、隐藏内容、合并重复问题或文献。
- 所有关键流程在网站和插件中都有错误状态和回退路径。

## 14. 后续细化建议

本 PRD 已确定产品方向、第一版范围、核心模块、权限、数据对象、筛选排序、系统架构、插件边界、UI 风格和验收标准。

下一步建议进一步细化每个任务的内容和代码架构设计，保证目标实现，各部分之间逻辑完整、连接而不冲突，并把实现细节拆到可执行任务级别。
